2d unwrapequirectangular, seam at ±180°

3D view is M0 (site distribution and cell boundaries from buildPlanetGraphCore()) — the near-side cull only holds up for a far/orbit camera, see runbook 022. The 2D unwrap's plates/elevation/land modes are M1 (buildPlanetTectonics()). The temperature/moisture/biome/rivers modes are M2 (buildPlanetEcology()): latitude+elevation climate, Whittaker biome lookup, river tracing, and coastline extraction — rivers mode overlays traced river paths and closed coastline loops on the land/water base. "3D preview" (M3) is a flat-shaded triangle-fan mesh, one fan per cell, colored by whichever 2D mode is active — a debug view, not a finished renderer. Every vertex is now pushed out by cellCornerElevation() (M4a's O(1) lookup) using its raw, unclamped blended elevation; land/water color is classified from that same per-vertex value (not a separate coarse per-cell flag) so color can never contradict height, and a separate sea-level ocean shell sits on top to visually cover submerged terrain. No beach/sand band — tried and reverted, since a thin band isn't achievable via vertex color at this mesh resolution (any tint is at least a full triangle wide). 3D preview is now chunked (M4b, one draw call per ~100-cell chunk) with 2 discrete LOD levels per chunk (M4c): LOD0 is full per-cell detail, LOD1 merges neighboring cells into single flat polygons over their shared outer boundary, and the two never crack against each other because a merged polygon's boundary vertices are the exact same corner objects (and numerically the same elevation) LOD0's cells use along that border — no skirts, no stitching pass. How far LOD1 merges is bounded by a curvature-error budget, not a cell count: a flat polygon spanning a spherical cap of angular radius r sits 1 - cos(r) below the sphere, so collapsing a whole chunk to one polygon (the first thing tried here) buries it deep inside the planet — a sag an order of magnitude past the entire terrain relief, which renders as land sunk under the ocean shell with the chord plate's triangles fanning out through it, not as a recognizably coarse surface. A cell-count cap doesn't bound that either, since BFS-grown groups come out stringy rather than disc-shaped and a short string spans a wide angle. At the low end of the cell-count slider the budget already fits inside one cell, so LOD1 there is simply cell polygons minus their fan centers (a third fewer triangles); the merge only starts paying off at higher cell counts, which is the point — the LOD saves more where there is more to save. Merging can still make a locally prominent peak, coastline cape, or small island flatten, shift, or vanish when a chunk crosses the LOD0/LOD1 boundary, so a small per-chunk budget of cells — the most prominent peaks, sharpest coastline curvature points, and biggest small islands, ranked and capped rather than pinned past a fixed threshold (a threshold regresses hardest exactly where a chunk is genuinely mountainous, since most of its cells would clear a fixed bar) — is pinned to always render as its own single-cell polygon at both LODs, so those specific features stop popping regardless of camera distance. The camera-distance threshold for the LOD0/LOD1 switch is the "LOD distance" slider; the "LOD split" stat shows how many chunks are currently at each level, and the "chunk colors" toggle colors each chunk mesh flat (one hash color per chunk, shared by both its LOD meshes) so chunk/LOD boundaries are visible directly. Rivers mode overlays traced river paths (elevation-following) and a coastline "waterline" extracted directly from each chunk's LOD0 mesh triangles (not the coarser per-cell chain, and never LOD1's), so it always matches the terrain's land/water edge exactly and stays stable regardless of the live LOD state — independent of the 3D preview toggle. The "collider patch (M4d)" toggle renders a separate magenta wireframe grid built by buildColliderPatch(), sampling sampleElevation() directly at whatever "patch resolution"/"patch width" ask for, centered on wherever the camera is currently looking. It has no relationship to chunk boundaries, chunk LOD, or cellCount at all — that independence is the point (runbook 022 Layer 2/3's camera/physics decoupling): the patch stays uniformly fine underneath the probe point even where the chunk mesh beneath it has dropped to LOD1's merged polygons. This is a rendering proof only so far, not a physics one — no Jolt body yet, that's the next M4d step.
